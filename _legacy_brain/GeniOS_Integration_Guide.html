§ 01 — Overview

What GeniOS Provides

GeniOS is the brain layer for any AI agent or product that touches people-related data — emails, calendars, contacts, documents.

It runs continuously across a customer's connected tools (Gmail, Calendar, Docs, Drive, Slack, Jira, Notion, HubSpot) and exposes five capabilities through a single API surface:

CapabilityDescription
Relationship intelligence Stage WARM AT_RISK COLD NEEDS_ATTENTION, EWMA sentiment, sentiment trend, communication style, authority score, freshness score.
Commitments & Anomalies Auto-extracted from emails — who promised what, when, status. Plus z-score anomaly flags on sentiment/engagement drops.
Proactive insights 50+ detectors fire when something matters: going cold, overdue commitment, anomaly, role change.
Live tool fetch When the cached graph misses, GeniOS calls Gmail / Calendar / Docs in real time.
Reasoning + actions Every response includes a ready-to-use paragraph, agent guidance ("do / avoid"), and a concrete next step.
Pitch — one sentence

Pipes (your inbox / phone / CRM) + GeniOS (the brain) = an agent that actually understands context.

§ 02b — Two Modes

Reactive vs Proactive — how each path delivers

Every path supports both modes — but the wiring differs. Read this once, then pick.

Mode What it means How GeniOS delivers it
Reactive You ask — GeniOS answers. Triggered by your code / agent / user query. Hit POST /v1/context (or its MCP / SDK / LangGraph wrapper). Returns a 35-field intelligence bundle in < 400 ms (cached) or 2–12 s (live fetch). Includes reasoning, anomalies, agent guidance — not just a memory dump.
Proactive GeniOS notices something you didn't ask about — going cold, overdue commitment, anomaly — and surfaces it. Two mechanisms: (a) Poll GET /v1/insights on a schedule (works today, ~800 ms response). (b) Subscribe a webhook — GeniOS pushes when a detector fires (manual setup with your rep currently).

Per-path support matrix

Path Reactive Proactive (today) Proactive mechanism
REST API YES YES Poll GET /v1/insights every 5–15 min from your backend
MCP Server YES YES The agent's LLM calls genios_list_insights when the user asks "what should I know" / "any alerts". Plus optional pending_alerts piggyback on every tool response.
LangGraph Node YES YES Add a periodic node (or scheduled graph entry) that calls /v1/insights and routes to the appropriate action node.
Webhook — SETUP Customer-self-serve registration not in dashboard yet — contact your GeniOS rep to wire up your endpoint URL.
Python / Node SDK YES YES Wraps /v1/insights — call client.insights() on a timer, or use SDK's helper schedulers if available.
Recommendation

For first integration, do REST (or MCP) for reactive + poll /v1/insights every 10 min for proactive. This gives you full brain behaviour with zero infrastructure. Upgrade to webhook push when you need sub-minute alerting.

MCP Server

Zero-code for MCP-compatible agents · 5 min to set up.

When to use it

Your agent already speaks MCP (Model Context Protocol) — Claude Desktop, Cursor, Claude Web, ChatGPT, Cline, Windsurf, Zed, or any custom MCP client. No code change needed in the agent itself. The LLM auto-discovers GeniOS tools and decides when to call them.

Setup · Claude Web / ChatGPT

  1. Settings → Connectors → Add custom connector
  2. Name: GeniOS
  3. URL: https://squid-app-2zuqf.ondigitalocean.app/mcp
  4. Advanced settings → Authorization → Bearer token → paste gn_live_xxxxx
  5. Save → Connect → done

What the LLM does

The agent's LLM sees the tool list and calls them naturally:

  • "What's the latest with Alice?" → calls genios_get_context
  • "Anything I should know today?" → calls genios_list_insights
  • "Find Razorpay invoices in my email" → calls genios_live_search

Proactive layer in MCP

MCP gets you proactive intelligence two ways:

  1. User-initiated — "Anything I should know today?" → LLM auto-calls genios_list_insights → surfaces priority items.
  2. Scheduled inside the agent — for headless agents, schedule a tool call to genios_list_insights on a timer (every 5–15 min). Each pulled item routes to the appropriate action handler.
  3. Pending alerts piggyback — every genios_get_context response may include pending_alerts. The LLM is instructed to surface those naturally as "By the way, the brain noticed...". Best for chat-style agents where users are actively engaged.
Recommendation

For chat agents (Claude, ChatGPT) — the LLM already calls genios_list_insights when relevant; no scheduler needed. For headless / background agents (Inkbox-style) — combine genios_get_context on event with a scheduled genios_list_insights for proactive coverage.

§ 05 — Path 3

LangGraph Node

For graph-based agents · 2 hrs to integrate.

When to use it

Your agent is built with LangGraph — the most common framework for production AI agents. GeniOS slots in as a dedicated node in the agent graph.

Architecture

Inbound trigger (email · scheduled) ↓ ┌─────────────────────────┐ │ fetch_genios_context │ ← GeniOS REST call └─────────────┬───────────┘ ↓ ┌─────────────────────────┐ │ draft_reply (LLM) │ ← uses ctx in prompt └─────────────┬───────────┘ ↓ ┌─────────────────────────┐ │ send_via_<channel> │ ← Inkbox · Gmail · etc └─────────────────────────┘

Code · LangGraph (Python)

agent.pypython
from langgraph.graph import StateGraph, END
from typing import TypedDict
import requests

class AgentState(TypedDict):
    incoming_email: dict
    genios_context: dict
    draft_reply: str

GENIOS_URL = "https://squid-app-2zuqf.ondigitalocean.app"
GENIOS_KEY = "gn_live_xxxxx"

# Node 1 - pull GeniOS context
def fetch_genios_context(state: AgentState) -> AgentState:
    email = state["incoming_email"]
    response = requests.post(
        f"{GENIOS_URL}/v1/context",
        headers={"Authorization": f"Bearer {GENIOS_KEY}"},
        json={
            "entity": email["from"],
            "situation": f"replying to: {email['subject']}"
        }
    ).json()
    return {**state, "genios_context": response}

# Node 2 - draft reply with context
def draft_reply(state: AgentState) -> AgentState:
    ctx = state["genios_context"]
    email = state["incoming_email"]
    prompt = f"""Reply to this email using the relationship context.

CONTEXT:
{ctx['context_for_agent']}

Stage:           {ctx['entity']['relationship_stage']}
Sentiment:       {ctx['entity']['sentiment_ewma']} ({ctx['entity']['sentiment_trend']})
What works:      {ctx['entity'].get('what_works', '')}
What to avoid:   {ctx['entity'].get('what_to_avoid', '')}
Agent guidance:  {ctx.get('agent_behavior', {})}
Suggested:       {ctx['action_recommendation']}

EMAIL:
{email['body']}
"""
    reply = llm.invoke(prompt)
    return {**state, "draft_reply": reply}

# Node 3 - send
def send_email(state: AgentState) -> AgentState:
    inkbox.email.send(
        to=state["incoming_email"]["from"],
        body=state["draft_reply"]
    )
    return state

# Build the graph
graph = StateGraph(AgentState)
graph.add_node("fetch_context", fetch_genios_context)
graph.add_node("draft", draft_reply)
graph.add_node("send", send_email)
graph.add_edge("fetch_context", "draft")
graph.add_edge("draft", "send")
graph.add_edge("send", END)
graph.set_entry_point("fetch_context")

agent = graph.compile()
agent.invoke({"incoming_email": {"from": "alice@acme.com", "subject": "...", "body": "..."}})

Why LangGraph specifically

PropertyBenefit
State persistsGeniOS context is available across every later node — no re-fetching.
ResumableIf the agent crashes mid-workflow, it restarts from the last node with context intact.
ObservableEach node's input/output can be logged independently for debugging.

Proactive layer · scheduled "watch" sub-graph

Add a separate scheduled graph that polls /v1/insights and routes each high-priority item to your action graph. Two graphs, one shared state schema:

watch_graph.pypython
from langgraph.graph import StateGraph, END

# Node 1 - poll proactive insights
def poll_genios_insights(state):
    r = requests.get(
        f"{GENIOS_URL}/v1/insights?limit=10",
        headers={"Authorization": f"Bearer {GENIOS_KEY}"}
    ).json()
    high_pri = [i for i in r["insights"] if i["priority"] in ("P1", "high")]
    return {**state, "pending": high_pri}

# Node 2 - dispatch to action
def dispatch(state):
    for i in state["pending"]:
        if i["type"] == "anomaly":
            send_alert_to_human(i)
        elif i["type"] == "state":
            invoke_followup_agent(i)
    return state

watch = StateGraph(dict)
watch.add_node("poll", poll_genios_insights)
watch.add_node("dispatch", dispatch)
watch.add_edge("poll", "dispatch")
watch.add_edge("dispatch", END)
watch.set_entry_point("poll")

watch_agent = watch.compile()

# Run via cron / Celery / setInterval every 10 min
while True:
    watch_agent.invoke({})
    time.sleep(600)

§ 08 — Auth

Authentication

All requests require a Bearer token in the Authorization header.

HEADER Authorization: Bearer gn_live_xxxxxxxxxxxxxxxxxxxxxxxxx

Get your key

  1. Log in to https://brain.thegenios.com
  2. Settings → API Keys → Generate Key
  3. Copy the gn_live_... token (shown once)
Security

Treat the key like a password. Each call is rate-limited per key based on plan tier. Rotate immediately if exposed.

§ 13 — Verify

Quick Verify (30 seconds)

Run this curl to confirm your integration is wired correctly:

verify.shbash
curl -X POST https://squid-app-2zuqf.ondigitalocean.app/v1/context \
  -H "Authorization: Bearer gn_live_xxxxx" \
  -H "Content-Type: application/json" \
  -d '{"entity":"Alice Chen","situation":"follow up"}'

You should see a JSON response with entity, context_for_agent, action_recommendation, confidence, intent_signal, scores, and latency_ms fields. If you see this — integration is working.
