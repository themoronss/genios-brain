How this was read, and why it is safe

scripts/pipeline_funnel_report.py is 33 select statements, zero insert/update/delete/DDL, behind set transaction read only issued at the server — Postgres itself would refuse a write. Its guard nevertheless demands GENIOS_ALLOW_PROD_WRITE=1, because the guard does not distinguish reads from writes. Rather than assert a write permission this work never needed, the same 33 queries were run through a read-only session. Nothing on this page came from re-running the pipeline.

The two hold reasons are one starvation

349 candidates carry both qes_required and verified_evidence_required, which reads like two independent defects. It is one. _preflight raises qes_required when importance_source is not l1_qualified_signals; importance_base() returns that arm only when an L1 bundle arrived — the same bundle the evidence gate is waiting for. Feeding the bundle clears both.

7. What to fix next, in the order the data justifies

  • The headline template. The card already holds better prose than it displays. Cheapest large improvement available, and it is a rendering change, not an intelligence one.
  • Deploy the branch and re-read this page. Every claim above about what would change is still a claim. admitted has sat at 18 across two runs; that number is the one to watch.
  • ambiguous_over_budget at 69. The largest ESQE outcome is "we did not decide". Raising the ceiling costs money and is the budget owner's call — but it should be a decision, not a default.
  • The sales pack on an admin tenant. 270 of 512 candidates, holding the top of the utility table, in a mailbox with no customers. Deactivating sales here is a configuration change.
  • Carry capability_key onto the card. 381 packages compiled, zero cards say which one they used. Without it, L3's contribution is unauditable.
  • The three empty brains. Behaviour, organization rules and adaptive preferences are 0 in all 381 packages. Everything in READINESS.md §6 still stands.
