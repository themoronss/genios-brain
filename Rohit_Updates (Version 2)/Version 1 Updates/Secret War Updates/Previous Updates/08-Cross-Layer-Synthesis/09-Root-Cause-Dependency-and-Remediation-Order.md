# Root-Cause Dependency and Remediation Order

## Blunt diagnosis

The weak intelligence is not caused by one prompt, one model, one Sales rule, or one frontend card. The product has several strong local subsystems, but the authoritative semantic chain is broken at multiple boundaries. Upstream ambiguity is converted into a valid-looking object; draft/unreviewed expertise passes a resolver with no review-state admission; incomplete expertise falls through to legacy generic rules; three runtime brains currently have hash-only influence rather than decision influence; a thin decision is projected as a confident imperative; the visible action is not one accountable execution; delivery truth is split; and fragmented/governance-broken outcomes cannot reliably improve the next decision.

The primary Root cause is therefore **loss of typed business meaning and authority across boundaries**, followed by **parallel old/new paths that allow a weaker result to remain customer authority**. More YAML or a stronger LLM before these seams are repaired will make the same error more fluent.

## Dependency map

```text
RC-1 Qualified evidence + roles + permission
        ↓
RC-2 bounded current BusinessSituation / open loop
        ↓
RC-3 reviewed/accepted authoritative expertise or authoritative abstention
        ↓
RC-4 semantically consumed brains + gold decision + lossless card
        ↓
RC-5 one accountable execution truth
        ↓
RC-6 one fenced delivery/result truth
        ↓
RC-7 canonical outcome → governed review/policy/lifecycle → future semantic decision

RC-8 scope/origin/authority envelope constrains every arrow.
RC-9 health, golden replay and pilot evidence gate every promotion.
```

This dependency is conjunctive. Building RC-7 before RC-1/RC-2 trains on wrong identity/state. Activating RC-3 before deep capability closure replaces generic legacy errors with compiler-backed gaps. Moving to v2 Delivery before RC-4/RC-5 sends the wrong action more reliably. A prettier card before RC-2/RC-4 makes ambiguity easier to trust.

## Remediation order and deliverables

### 1. Stop unsafe authority expansion

- Keep new compiler scoped/shadow until a promotion key passes.
- Make uncovered/stub/draft/unreviewed/unaccepted expertise an authoritative non-action; block legacy generic fallback.
- Keep agent handoff unavailable.
- Surface source/context/expertise readiness and suppress completed/superseded cards.

### 2. Repair semantic boundaries

- Version QES and BSO mappings rather than modifying contracts silently.
- Introduce typed business roles and one bounded `open_loop_id`/relationship/opportunity/thread membership.
- Stamp/narrow visibility and permitted use; preserve source readiness and negative-evidence eligibility.
- Make correction invalidation transitive and version-fenced.

### 3. Build one deep intelligence lane

- Ratify `buying_signal → sales.sit.inbound_fit_check → sales.qualification.lead_qualification`, with `sales.market_and_targeting.icp_definition` as companion; keep Theresa/fundraising outside authority until separately authored, reviewed and accepted.
- Complete objects, rules, plays, failures, routes, counterexamples and golden fixtures.
- Enforce review-state admission for every retained capability/dependency. Compile Expert + Organization + Behavior + Adaptive snapshot; label absent/sparse brains honestly and prove each selected runtime brain's semantic influence with a pinned mutation.
- Run full reasoning manifest appropriate to the scenario and produce the gold decision contract.

### 4. Weld decision to accountable operation

- Atomically turn a card action into a native execution command.
- Ratify Executive versus Delivery routing ownership in an ADR.
- Migrate to one canonical DeliveryObject/Result and fenced sender.
- Track action, send, delivery, completion and external result separately.

### 5. Close learning and value proof

- Reconcile feedback/outcomes to one identity and counterfactual.
- Promote only bounded versioned brains under lossless use/policy/population/review/lifecycle gates; Organization approval without a brain row remains `approved_unpublished`, stored/loaded policy must match, and non-expiring Adaptive remains blocked.
- Require `brain_snapshot_id` plus typed semantic-consumption receipt and intended decision change; a changed hash with identical judgment is failure.
- Replace hardcoded analytics with canonical ledger metrics; measure real pilot lift.

## Do not do

| Tempting shortcut | Why it fails |
|---|---|
| Turn on the domain compiler globally | Most corpus capabilities remain stub/unrouted; all non-stub capabilities are draft/unreviewed; review-state admission is absent; active situation semantics are unsafe |
| Ask a stronger model to “use all context” | It cannot repair wrong role, visibility, current state, permission or causal outcome; it can hide missingness |
| Author all 152 capability files in parallel | Volume creates review debt and no vertical customer proof; one accepted deep lane teaches the real schema |
| Tune urgency/confidence thresholds from screenshots | Score is already conflated with confidence; thresholds cannot invent expertise or completion |
| Build a new dashboard first | Product truth remains wrong; presentation cannot establish execution/outcome/learning |
| Connect more agents before origin/lease/result contracts | Wrong intelligence executes faster, loops recursively and double-learns |
| Count click/delivery/closed deal as GeniOS value | Exposure, action, outcome and causal attribution are different facts |

## Release decision

The Remediation order is vertical, not layer-by-layer completion. Promote one narrow customer-value slice only when every upstream Dependency is green and every unsupported branch fails closed. The first credible claim is not “Layer 3 has 46 Sales files” or “all seven layers exist.” It is: **for a labelled situation, GeniOS identified the correct subject and current loop, applied named-reviewer accepted expertise, proved the semantic effect of each selected brain, chose a superior specific action or honest no-action, created accountable work, delivered once, observed the declared result, and used it through policy-faithful, lifecycle-valid learning to change only the intended later decision.**

Until that chain and a real counterfactual pilot pass, the correct system status remains **framework-rich, unsafe for broad prescriptive authority, and not Outcome-proven**.
