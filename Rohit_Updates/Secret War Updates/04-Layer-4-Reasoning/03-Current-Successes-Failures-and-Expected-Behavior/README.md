# Layer 4 — Current Successes, Failures, and Expected Behavior

**Evidence baseline:** `harsh/mvp@b739bd5ca682d09550acc400ed2892c38c8518f8`, audited 2026-08-22. `[CODE]` proves repository behavior, `[SCREENSHOT]` proves only the rendered examples, and `[ATLAS]` defines the expected boundary. The screenshots do not prove which internal branch produced every field; source tracing establishes the available active/fallback paths.

## Blunt operational reading

Layer 4’s engine is architecturally ahead of its output. The repository has deterministic orchestration, 17 registered reasoning units, candidate elimination/ranking, typed abstention and a tightly bounded explanation LLM. The active adapters and card projection discard much of that power: usually one generic play enters a six-unit DAG, and stakes/completion/alternatives do not survive to the card. The visible result is an activity reminder with a confidence badge, not consultant-grade judgment.

## What is genuinely successful

The decision maker’s ordering—hard elimination before total-order ranking—is correct. Confidence authority is centralized, and below-floor decisions can return no selected candidate. The explanation model is not allowed to change the deterministic action/confidence and must ground its text. These are meaningful safety properties, not placeholders.

The important qualification is reachability. `reason/reasoners/__init__.py:41-65` registering all 17 units does not mean `SALES_V1` or `GENERAL_V1` schedules them. `packs/capabilities/__init__.py:16-22` explicitly excludes the full 17-unit candidate from manifest sweep while retaining a shadow-first baseline. Current output quality is therefore consistent with the code: a sophisticated engine is fed thin plays and projected through generic templates.

The second qualification is semantic consumption. Layer 3 can prove that Organization, Behavior and Adaptive entries were selected because they affect `knowledge_hash` and manifest version. Layer 4 currently cannot prove that their values affected a decision. Hash inequality is provenance evidence, not behavioral evidence; the decision trace must expose the exact constraint, candidate, rejection or ranking term derived from each selected brain entry.

## Required behavior

A valid authoritative decision must contain a state-based situation, exact remaining loop, primary candidate, materially different fallback when feasible, explicit wait/stop option, rejection receipts, business stakes, expiry, separated confidence vector, owner/approval boundary, observable completion and outcome window. If the upstream package cannot support those fields, the correct behavior is `DEFER`/`INSUFFICIENT_CONTEXT`/review source—never a generic imperative generated simply because a message or calendar row exists.

## Verdict

Layer 4 is **framework-ready, not live-ready**. Its deterministic core has verified strengths, but the active one-play/six-unit path and lossy card projection are unsafe for the high-confidence prescriptive experience shown. The remedy is not to weaken gates or add an unconstrained LLM; it is to deliver richer candidates, schedule the required reasoning units, preserve abstention, and make stakes/completion/alternatives mandatory.
