# Layer 7 Learning — Loopholes, Edge Cases, and Fail-Closed Catalog

## Purpose

This catalog attacks the difference between “the learning job ran” and “the system learned a justified lesson.” A Loophole is a path that can satisfy present checks while violating the intended guarantee. An Edge case is a legitimate operating shape that must remain safe. The required Fail closed result is always an observable state—reject, quarantine, retain as observation, request review, or publish nothing—not a silent drop.

## No-silent-drop contract

Every rejected or deferred candidate must retain `run_id`, tenant, unit, evidence IDs, reason code, failed gate, policy version, timestamp, and recovery status. “No proposal” is valid only when accompanied by a machine-readable reason such as `insufficient_independent_support`, `outcome_unreconciled`, `visibility_forbidden`, `identity_unresolved`, or `ttl_missing`. A weekly sweep that returns zero objects without this accounting is operationally indistinguishable from broken wiring.

The three pinned authority failures also require explicit durable dispositions:

| Failure | Required disposition | Prohibited continuation | Recovery receipt |
|---|---|---|---|
| Review approval has no brain publication | `approved_unpublished` | `promoted`, active-learning count, or future-package influence without a brain version | Review actor/policy revision, immutable proposal hash, one publisher result, learned brain/version and compiler-consumption ID |
| Loaded policy omits block lists | `policy_incomplete` and abort tenant run | Continue with default `blocked_targets=()` / `blocked_subject_prefixes=()` | Stored revision hash equals loaded `LearningPolicy`; both restriction lists and preflight decisions replay identically |
| Adaptive proposal cannot encode expiry | `adaptive_ttl_unresolved` / no brain publication | Durable Adaptive row or “short-horizon learning active” claim | Ratified TTL/decay policy, expiry/supersession event, zero post-expiry selection and rollback lineage |
| Reset receipt says `adaptive_expired` although only Runtime rows changed | `durable_brain_reset_incomplete` | Claim that Organization, Behavior, or durable Adaptive was invalidated; treat situation rerun as invalidation | Pre/post counts and versions for `temporary_memories` plus every learned brain, explicit durable transitions, snapshot invalidations, and compiler-consumption receipts |

## Fail-closed priority

1. Protect tenant, identity, visibility, and permitted use.
2. Refuse efficacy updates without delivery, action, and external-outcome reconciliation.
3. Keep sparse or ambiguous evidence as observation, never global truth.
4. Require exact policy-load fidelity before a unit runs; stored restrictions may never disappear into constructor defaults.
5. Require version, target, expiry where applicable, policy, publisher receipt, compiler-consumption receipt, and rollback before activation; expiry applies to Runtime temporary memory under current code, not to durable learned brains.
6. Treat human approval and publication as separate states; approval alone cannot manufacture an active brain value.
7. Treat reset and durable-brain invalidation as separate operations: reset expires Runtime leases, while Organization, Behavior, and durable Adaptive require explicit governed supersession/deactivation plus snapshot invalidation.
8. Surface degraded learning health to operators and customers; do not label a no-op sweep, a Runtime-only reset, or a non-expiring learned value as adaptive intelligence.

The safe failure is delayed or absent personalization with an explicit recovery path. The unsafe failure is a confident learned rule whose evidence, role, scope, causality, or permitted use cannot be reconstructed.
